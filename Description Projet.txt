-= BUT =-
---------
L'application « Membres Soc FrenchJumper » est l'outil de gestion des membres de la société FrenchJumpers dans Entropia Universe.

Elle permet notamment :
- d'afficher les membres actifs et les anciens membres ;
- de rechercher et consulter la fiche individuelle d'un membre ;
- de créer la fiche d'un nouveau membre ou de rouvrir celle d'un ancien membre ;
- d'enregistrer les entrées, promotions, rétrogradations, sorties, désertions et bannissements ;
- de conserver l'historique chronologique des mouvements et des grades ;
- de modifier les informations complémentaires d'une fiche ;
- d'associer un membre à son identité Discord ;
- de synchroniser certaines conséquences avec Discord, notamment le retrait du rôle « Règlement Soc OK » lors d'une sortie ;
- de fonctionner normalement sur Cloudflare Workers + D1, avec Google Sheets + Apps Script comme backend de secours ;
- de synchroniser les mutations entre D1 et GAS avec reprise, déduplication, audit et contrôle des écarts ;
- de protéger les actions RH par une authentification Discord et par la vérification des rôles autorisés.

Grades connus, du niveau 0 au niveau 6 :
0. Ancien Membre
1. Voyageur
2. Voyageur Expérimenté
3. Aventurier
4. Aventurier Expérimenté
5. Conseiller d'Expédition
6. Chef d'Expédition (grade unique)

Règles métier importantes actuellement codées :
- une nouvelle entrée réactive un « Ancien Membre » comme « Voyageur » ;
- une sortie, une désertion ou un bannissement place le membre en « Ancien Membre » ;
- une désertion n'est autorisée que depuis le grade « Voyageur » ;
- les promotions et rétrogradations suivent les niveaux autorisés ;
- aucune action de mouvement n'est permise sur le Chef d'Expédition ;
- les mouvements de sortie retirent également l'acceptation locale du règlement ;
- la synchronisation Discord associée n'est déclenchée qu'après la réussite de l'opération métier concernée.

-= ARCHITECTURE =-
-------------------
Frontend statique GitHub Pages :
- pages principales : index.html, actifs.html, anciens.html, fiche.html, mouvements.html, nouveau.html et sync.html ; page technique de retour OAuth : oauth-callback.html ;
- logique cliente partagée : js/config.js, js/client.js, js/utils.js et js/oauth-callback.js ;
- styles : css/style.css ;
- le paramètre « admin=1 » est désormais obsolète dans le code local : il est retiré de l'URL et ne constitue jamais une autorisation ;
- le bouton Connexion/Déconnexion Discord est toujours visible en bas du menu de `index.html` ; l'affichage RH dépend de `/auth/session` ;
- D1 est prioritaire ; une sonde « /health » peut activer GAS en mémoire, sans redirection ni modification des liens, en cas d'indisponibilité ;
- les liens internes ne contiennent jamais le paramètre « backend » ; les commandes ponctuelles « ?backend=gas » et « ?backend=d1 » sont consommées au chargement puis retirées de l'adresse.
- les fonctions et activités Discord sont affichées publiquement sous forme de badges ; les catégories vides restent masquées et les responsabilités Discord sont semi-privées, visibles en accès RH ou en Consultation FRJ.

Backend principal Cloudflare :
- projet : cloudflare/membres-soc-api ;
- Worker : frj-membres-soc-api ;
- base : Cloudflare D1 ;
- migrations versionnées : 0001_initial.sql, 0002_bidirectional_sync.sql, 0003_discord_role_cache.sql et 0004_reduce_discord_role_writes.sql ;
- modules principaux : index.js, auth.js, domain.js, discord.js, discord-roles.js et sync.js ;
- files métier : frj-membres-sync et frj-membres-sync-dlq ; file dédiée aux lectures de rôles : frj-discord-role-sync et frj-discord-role-sync-dlq ;
- contrôle planifié une fois par jour à 03:17 UTC ;
- Service Binding vers le Worker « discord-proxy » existant ;
- tests Node couvrant l'authentification, le métier, Discord, le frontend et la synchronisation.

Backend de secours Google :
- Google Sheets conserve les grades, membres, mouvements et données de synchronisation ;
- gas/Code.gs expose le contrat HTTP historique et les opérations métier ;
- gas/Sync.gs gère la réplication, l'outbox, les reprises et les modifications manuelles de la feuille ;
- la feuille masquée SYNC_OUTBOX conserve les mutations GAS en attente ;
- le déclencheur installable « syncMemberManualEdit » capture les modifications manuelles utiles ;
- « flushSyncOutbox » retente les mutations qui n'ont pas encore été appliquées.
- les colonnes FonctionsDiscord, ActivitesDiscord, ResponsabilitesDiscord, RolesDiscordSyncedAt et RolesDiscordStatus conservent le cache de secours D-002 ; les responsabilités ne sont jamais exposées par la lecture publique.

Synchronisation :
- chaque mutation porte un UUID d'idempotence ;
- les mouvements sont append-only et dédupliqués par leur identifiant ;
- les versions d'entités servent à éviter les régressions et à identifier les conflits ;
- les réplications sont marquées par leur source et leur cible ;
- la file Cloudflare métier réalise les reprises vers GAS ; une file séparée et séquentielle limite les lectures de rôles Discord ;
- un cron relance les mutations en attente et compare périodiquement les compteurs D1/GAS ;
- sync.html fournit le tableau d'administration de la synchronisation.

- noter dans « Réalisations effectuées » le résultat exact, les versions publiées et la recette réalisée.
